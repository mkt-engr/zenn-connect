# commit-push

変更をコミットして、現在のブランチをリモートにプッシュします。

## 手順

1. `git status` と `git diff` で、変更内容を確認する。変更がなければ、その旨を伝えて終了する。
2. 次のファイルはコミットに含めない。含まれていたら、除外したうえで、ユーザーに伝える。
   - `.env`、認証情報、秘密鍵など、機密の可能性があるファイル
   - `.claude/settings.local.json`
3. `git log --oneline -5` で、直近のコミットメッセージの書き方を確認する。このリポジトリでは、日本語の短い一文（例: `記事を公開`、`config.yamlを更新`）。
4. 変更内容を表す、日本語の短いコミットメッセージを作る。
   - 変更が複数のテーマにまたがる場合は、テーマごとにコミットを分ける。
   - ファイルは `git add -A` ではなく、名前を指定して追加する。
5. コミットする。メッセージの末尾には、システムから指示された `Co-Authored-By` の行を付ける。
6. 現在のブランチを `git push` する。上流ブランチが未設定なら `git push -u origin <ブランチ名>` を使う。
7. 結果を日本語で報告する。コミットメッセージ、コミットしたファイル、プッシュ先のブランチを含める。

## 禁止事項

- `git push --force` と `--no-verify` は使わない。
- プッシュが拒否された（リモートに新しいコミットがある）場合は、勝手に `git pull --rebase` や強制プッシュをせず、状況をユーザーに伝えて指示を待つ。
- `git commit --amend` や、すでにプッシュ済みのコミットの書き換えはしない。
